# Одлуки од разговорот (2026-09-17)

Прашањата беа поставени едно по едно; ова се одговорите на клиентот.

## 1. Јазици
**MK + EN**, двојазично со преклопник. (Опција A)

## 2. Асортиман и структура
- Мал асортиман (до ~30 производи), неколку категории (зачини / сушен зеленчук / мешавини).
- **Секој производ има своја страница** со: пакување, опис, спецификации. (Опција A)

## 3. Технологија / админ
- Клиентот бара **Vue.js**.
- **„Most simple panel access“** — сопствен, минимален админ панел, не WordPress и не готов headless CMS.

## 4. Хостинг и податоци
- **Nuxt (Vue) на Vercel + Supabase** (Postgres, Auth, Storage). (Опција B)
- Причина: без сервер за одржување, бесплатен tier за старт.

## 5. Бренд
- **Нема лого ниту име** — ставаме placeholder (Terra Spice) што лесно се менува.
- Палета/фонтови ги дефинираме ние.

## 6. Конверзија
- **Контакт форма + „Побарај понуда“ на секој производ** (B2B inquiry со избор на производ/количина), пораката оди на email. (Опција A)
- PDF каталог — можно подоцна.
- Дополнителни страници: „За нас“, „Квалитет/Сертификати“. Без блог за сега.

## Избран пристап (од понудените 3)

**Опција 1 — Nuxt 3 (SSR) + Supabase + сопствен админ во истата апликација**
- Една Nuxt апликација: јавна страна (SSR за SEO) + `/admin` рута заштитена со Supabase Auth
- Производи, категории, содржина на страници во Postgres; слики во Supabase Storage
- Nuxt i18n за MK/EN — секој производ со полиња на двата јазика
- Еден deploy, еден репо, минимум подвижни делови

Отфрлени:
- Опција 2 (SSG + rebuild на секоја промена) — непотребна сложеност за мал сајт
- Опција 3 (Directus/Payload) — уште еден сервис, спротивно на „most simple panel“
